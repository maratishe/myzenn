# VS Code Copilot Agent: Anthropic BYOK Sonnet 5.5 with a 200K Context Window

**Outcome:** We successfully registered a separate Anthropic-backed
**Custom Endpoint** in VS Code, made its Sonnet 5.5 model selectable in
Copilot Agent, and verified that VS Code reports **200K maximum
context**. After restoring a numeric output limit, requests succeeded. A
later single-model configuration displayed **High** thinking effort and
successfully answered a prompt.

> Scope of verification: The UI confirms the 200K budget and High
> selection, and a real request worked. We did **not** establish that
> the outgoing thinking parameters or input/output allocation are
> byte-for-byte identical to native Copilot's Sonnet 5.5 High (200K).

## Why we did this

The ordinary Anthropic BYOK model exposed a **1M** context window,
whereas native Copilot offered a clearly selectable **200K** option. For
large repositories, the larger window allowed individual agent requests
to accumulate very large amounts of source code and tool output,
increasing input-token consumption and cost. The goal was to preserve
**VS Code's Copilot Agent workflow and our own Anthropic API key** while
giving the agent a visible, deterministic 200K context budget---not to
impose a 200K session-wide spending cap.

We considered Claude Code and Cursor but found no comparably clear,
verified context selector for this setup. In the native Anthropic BYOK
definition, adding `contextSize: 200000` or `contextWindow: 200000`
under model settings did **not** change the UI's 1M indication. This led
us to the separate Custom Endpoint approach, inspired by [VS Code issue
#329892: Expose contextSizeOptions for BYOK
models](https://github.com/microsoft/vscode/issues/329892).

## Registering the Custom Endpoint in VS Code

The successful setup was tested in **VS Code 1.141.0**:

1.  Open the Command Palette and run **`Chat: Manage Language Models`**.
2.  Choose **Add Models → Custom Endpoint**.
3.  Give the provider a distinct name, for example
    **`si-sonnet-55-200k`**.
4.  Enter the Anthropic API key through VS Code's UI; VS Code stores it
    as a secret and writes an `${input:chat.lm.secret.…}` reference.
    **Keep the reference generated on your machine**; do not paste a raw
    API key into JSON.
5.  Choose the **Messages** API type.
6.  Open/edit **`chatLanguageModels.json`** using the generated provider
    skeleton. Set the Anthropic Messages endpoint URL, the actual API
    model ID, model capabilities, and context/output limits as below.
7.  Save; if necessary run **`Developer: Reload Window`**. Open Copilot
    Chat's model picker and select the new custom model.
8.  Inspect **Session Info → Context Window**. Our model showed
    **200K**, rather than 1M. A subsequent Agent prompt completed
    successfully.

The API model ID in the example below is the identifier used in our
working experiment. If your Anthropic organization exposes a different
ID, use the ID actually available to it.

## Understanding the two-level configuration

The JSON is a **two-level structure**, not a flat model configuration:

``` text
chatLanguageModels.json
└── Custom Endpoint / provider
    ├── name, vendor, apiKey, apiType
    └── models: [...]
        └── Model definition
            ├── id, name, url
            ├── toolCalling, vision
            ├── thinking / reasoning-effort metadata
            └── contextWindow, maxOutputTokens
```

The outer object registers a **provider-like endpoint**, including its
credential and API type. The nested `models` array defines models and
their individual parameters.

**Important practical finding:** Although the schema has an array and
appears to allow multiple models, when we put Medium and High entries
with the **same API model ID** into one endpoint, **only the first
(Medium) appeared/took effect**. Reducing the array to one High entry
made High appear. This observation does not prove that *all* multi-model
endpoints are unsupported; duplicate model IDs may be the cause. For our
reliable working setup, treat **one Custom Endpoint as a pair: one
provider definition + one model definition**, expressed together in one
JSON object. To register separate variants, create separate providers
and test each rather than assuming two same-ID entries in one array will
work.

## Final working configuration: 200K / High

This reproduces the **single-model High configuration** from our
experiment. The secret reference is installation-specific; retain the
one generated by your VS Code. The reasoning fields are the fields we
tried and that led to **High appearing in the UI**; we have not
independently inspected the outgoing Anthropic thinking payload.

``` json
[
  {
    "name": "si-sonnet-55-200k",
    "vendor": "customendpoint",
    "apiKey": "${input:chat.lm.secret.2feac303}",
    "apiType": "messages",
    "models": [
      {
        "id": "claude-sonnet-5-5",
        "name": "Sonnet 5.5 (200K High)",
        "url": "https://api.anthropic.com/v1/messages",
        "toolCalling": true,
        "vision": true,
        "thinking": true,
        "supportsReasoningEffort": ["high"],
        "reasoningEffortFormat": "messages",
        "contextWindow": 200000,
        "maxOutputTokens": 64000
      }
    ]
  }
]
```

### Why `maxOutputTokens` is present

Our first version omitted both `maxInputTokens` and `maxOutputTokens` to
avoid limiting generated code/documentation. The model was selectable
and VS Code showed **200K**, but the actual request failed after retries
with Anthropic's error:

`400 invalid_request_error: max_tokens: Input should be a valid integer`

Anthropic's Messages API requires a numeric `max_tokens` **on each API
request**. Adding **`"maxOutputTokens": 64000`** fixed the error in our
test.

This **64K is a ceiling for one model API response, not for a user's
prompt or an entire Agent session**. A single user prompt can trigger
multiple model calls interleaved with file reads, tools and edits; each
call has its own output ceiling. A 3--20-line edit does not consume 64K
simply because that maximum is configured. Actual model output,
including applicable reasoning/tool-call content, is what matters.

With our values, VS Code treats the budgets approximately as:

  Budget                                               Tokens
  ---------------------------------- ------------------------
  Total context window                                200,000
  Maximum response allocation          64,000 per API request
  Derived input allocation                            136,000
  Total generated across a session       Not capped at 64,000

Thus **200K context is not the same as 200K usable input**. We have
matched native Copilot's displayed *total* context, but have **not**
established that its native 200K preset reserves the same output amount.
The custom setup may be more conservative on input than native Copilot.

## Verification and remaining differences

What we observed:

-   The model picker showed our custom provider and **Sonnet 5.5
    (200K)**; its details said **Max context: 200K**.
-   With 64K output configured, the Agent successfully handled a real
    prompt and Session Info displayed context usage against **200K**
    (for example, **56.8K / 200K**).
-   After reducing the configuration to one High entry, the chat footer
    showed **Sonnet 5.5 (200K High) \| High**; a subsequent prompt
    worked.
-   In one session, tool definitions alone accounted for roughly
    **19.3%** of 57.5K reported usage---an illustration of
    non-repository context overhead.

What remains **unverified**: exact parity with native Copilot's thinking
payload, native `max_output_tokens`, compaction behavior, caching and
per-task cost. Compare like-for-like tasks using input,
cache-read/cache-write and output tokens; also compare how much of a
repository each agent reads.

Finally, **a 200K window limits context per request, not cumulative
session consumption**. A long agent run can send overlapping context in
many requests, so caching, compaction and tool behavior still matter.

## Practical takeaway

For this setup, use **one endpoint object containing one model
definition**, set `contextWindow` to **200000**, and provide a valid
numeric `maxOutputTokens` (our tested value: **64000**). The result
preserves Anthropic BYOK inside VS Code Copilot Agent with an explicitly
visible **200K** context ceiling and a UI-visible **High** setting,
without proxy servers or environment-variable configuration.
